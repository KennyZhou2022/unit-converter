# v2.0.0

Major reliability, identity, and package-cleanup release for
`nist-unit-converter`.

## Highlights

- Renamed the distribution from `unit-converter` to `nist-unit-converter`; the
  Python import remains `unit_converter`.
- Added stable `unit_id` and `quantity_id` values, reviewed aliases, and direct
  NIST and UI classifications on every supported unit record.
- Added `can_convert()`, `compatible_units()`, stable-ID listing helpers, and
  direct UI category, subcategory, unit, and unit-ID queries.
- Corrected the manually confirmed NIST Appendix B.9 thermal-resistivity
  exponent from `6.938112E+04` to `6.938112E+00` through a traceable errata
  manifest.
- Added reviewed UI overrides and explicit `unmapped` records where the UI
  taxonomy has no semantically correct category.
- Standardized invalid rules, values, formulas, and arithmetic failures under
  `ConversionError`, while preserving specific unknown, incompatible, and
  ambiguous conversion errors.
- Resolved equivalent rounded factor paths deterministically and retained an
  error for genuinely conflicting shortest paths.
- Made catalog access mutation-safe and documented the active `decimal` context
  behavior without adding a package-specific precision option.
- Expanded coverage to every bundled direct rule and all 6,108 reachable
  ordered unit pairs, plus identity, alias, UI mapping, and wheel smoke checks.

## Cleanup

- Removed unused `category` and `subcategory` fields from the custom
  `Conversion` API and the associated runtime context indexes.
- Removed duplicate converter state used only to list direct rules.
- Reduced runtime conversion data to fields needed for arithmetic; NIST source
  classifications remain available in the unit catalog and development review
  data.
- Removed duplicate `label`, `all_units`, `all_unit_ids`, and
  `unit_record_count` fields from the machine-readable unit catalog.
- Moved the stable registry to `data/registry/` as a source-generation asset;
  wheels read the same identity fields directly from the unit catalog instead
  of shipping a second copy.
- Moved physical-quantity review data and pair-count generation code out of the
  runtime package.
- Consolidated bundled JSON loading and removed stale dependency declarations.
- Updated conversion data to schema v2 and the composed unit catalog to schema
  v3, with runtime version checks for mismatched package assets.

## Release Quality

- Made `pyproject.toml` the authoritative dependency declaration and added the
  reproducible `requirements/dev.lock` contributor lock.
- Added Ruff, mypy, MkDocs strict mode, generated-data checks, wheel-content
  inspection, installed-wheel smoke tests, and `twine check` to release
  automation.
- Updated README, MkDocs user documentation, schemas, ADRs, and release
  instructions to match the 2.0 implementation.

## Breaking Changes

- Install the distribution as `nist-unit-converter`. Existing Python imports do
  not change.
- `Conversion(..., category=...)` and `Conversion(..., subcategory=...)` are no
  longer accepted. Unit names must be unambiguous; bundled temperature value
  and interval labels remain explicitly qualified.
- Raw `get_unit_catalog()` records no longer contain `label`; use
  `display_name`. The derivable top-level `all_units` and `all_unit_ids` arrays
  and duplicate `totals.unit_record_count` value were also removed. Public
  `list_units()` and `list_unit_ids()` behavior is unchanged.

## Notes

- Existing display-name conversion calls remain supported. Stable IDs are
  recommended for persisted application data.
- The three-argument `convert(value, from_unit, to_unit)` interface is
  unchanged.
- Tag this release as `v2.0.0`. Automation publishes the wheel and source
  archive to the matching GitHub Release, not to PyPI.
